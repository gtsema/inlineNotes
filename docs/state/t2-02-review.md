## `t3-01` readiness

The create card owns the one seam `t2-02` deliberately did not ship: turning a live selection `Range` into code-point offsets of the stream. It must **feed** `buildAnchor` one and the same string that the mapper walks back: call `buildTextStream(root)` once per capture with `root` at or above the selection's common ancestor (`src/content/anchor/text-stream.ts:138`; element, text node, `Document` or `DocumentFragment` all work — `tests/content-anchor-text-stream.spec.ts:304-320`), then pass `stream.text` with half-open **code-point** offsets of the **trimmed** span. A boundary offset must be derived through the fragment that contains it: find the `TextFragment` whose `node` holds the boundary, then convert the local UTF-16 offset with that node's `nodeCodePointIndex(node.data)` (`:222`) and add `streamStart`; a local offset that lands inside an internal whitespace run must snap to that run's `starts` entry, because one stream code point covers several node units (`tests/content-anchor-text-stream.spec.ts:283-294` shows `'a\n\n b'`: 3 stream code points, `start=0`, `end=5`). Never `range.toString()`, `Range` offsets or `indexOf` results as anchor offsets. `options.fragments` must be the **real** number of fragments the span covers — the same count the mapping will produce (spec `:80`, model AC19) — and it is a stored hint only. `entry.text` must be exactly `normalizeText` of the selection span taken from that stream and must equal `anchor.text`, or `createEntryOnPage` refuses with `entry_invalid` (`A26`); `buildAnchor` returns `null` for a degenerate range, so whitespace-only or empty selections must never reach it. Because `A20` inserts a separator at every block boundary, a selection that stops at a block edge has a trimmed last code point: feed the trimmed span, not the raw range end, or the contextual window stops being a substring of the stream (`t2-01` remark `R3`) and the anchor silently degrades to bare-text matching. What the card and the display path must **read back** is `locateAnchor(root, anchor)` → `{ ok: true, fragments }` in document order, where `start`/`end` are UTF-16 offsets inside `node.data` and are the only numbers suitable for `Range.setStart`/`setEnd`; `streamStart`/`streamEnd` are code points and must never be handed to a `Range` (spec `:81`). `{ ok: false, code: 'anchor_not_found' | 'anchor_stale' }` → no card anchor, no highlight, no frame, no tooltip, entry still listed and deletable (spec `:82`, overlay spec `:60`). For N entries: build the stream once per re-resolve and call `locateAnchorInStream(stream, root, anchor)` per entry, with the same `root` (N7); rebuild on load, bfcache and SPA URL change (`A29`). Card placement (`A30`) may use the first resolved fragment's rect, but the create card's source is the selection itself, which already precedes any locate.

Residual risks for `t3-01-content-create-card`:
1. The selection → stream adapter is the entire correctness risk of the slice: an offset taken from a `Range` or `Range.toString()` instead of the fragment code-point map yields either an `entry_invalid` refusal or an anchor whose window never matches (silent fallback to bare-text search), with no core signal. Residual risks for `t2-03-core-overlap`:
1. Overlap must be computed on the **resolved** half-open code-point range, not the stored anchor: a stale entry has no range, and spec `:82`/`:85` do not say what happens when an existing entry is stale. Needs a PM ruling before the AC is written.
2. The `A20` separator code point belongs to no fragment (spec `:80`), and a resolved range that falls entirely on a separator is already refused as `anchor_stale` (`tests/content-anchor-locate.spec.ts:353-366`). Overlap must treat touching boundaries as non-overlap (spec `:67`) without treating the shared separator as shared content.
3. The check belongs inside `assertCreatable` in the spec'd order (name → selection → 256 → 20 → overlap → identical, spec `:39`); the `A26` guard sits between `assertCreatable` and the draft, and `tests/core-entry-store-write.spec.ts:238` (per-page cap) and `:875` (cap and empty-comment precedence) must keep passing.
4. Two entries whose anchors resolve to different copies of repeated text can overlap unexpectedly in one re-resolve pass; overlap rejection therefore needs the range the current stream produced for **each** existing entry, which raises the walk cost per create.
