## Before/after proof of the fix

Old code (`git show ec4ee45^:src/content/capture/selection-span.ts:186-198`): `from = Math.max(0, Math.min(start, streamText.length))`, `to = Math.max(from, Math.min(end, streamText.length))`, then `streamText.charAt(begin)` / `charAt(finish - 1)`, returning `{start: begin, end: finish}`. Both the clamp and the probes treat a code-point number as a UTF-16 index. New code (`:211-226`):

**Out direction.** `utf16IndexAt(streamText, start)` (`src/core/text-normalize.ts:83-93`) is total: `!(codePointOffset > 0)` → `0`, so a selection at offset 0 maps to index 0 with no loop; the walk stops on `units < text.length`, so an offset at or past the last code point returns exactly `text.length`. Consequences for the end-of-string probe: `charAt(finishUnits - 1)` at `:219` can therefore read index `text.length − 1` (the last code point's last unit) and never `text.length`; the leading probe at `:216` is gated by `beginUnits < finishUnits`, so it never reads at or past the end. The step is `+= 1` / `-= 1` and only ever taken when the probed unit is `STREAM_SEPARATOR = ' '` (`:229`), one UTF-16 unit, so a step from a code-point boundary always lands on a code-point boundary and can never split a surrogate pair — this is what the rewritten comment claims (`:204-206`) and it is true.

**Back direction.** `codePointOffsetAt(streamText, beginUnits)` (`text-normalize.ts:101-111`) counts whole code points up to the index; a landing mid-pair would round up, but the landing set is {`utf16IndexAt` outputs} ∪ {those ± separator steps}, all boundaries, so the pair is an exact inverse for every value this function can produce. The old version had no back conversion at all: it returned the stepped UTF-16 numbers as if they were code points.

**Astral at the start of the stream.** Fixtures `tests/content-selection-capture.spec.ts:332` (`<p>😀 alpha</p>`) and `:351` (`<p>😀 a</p>`) put the astral code point at stream position 0, so `utf16IndexAt(text, 2)` = 3 and the probes land on `'a'` instead of the old `' '` at unit 2.

**Selection at offset 0.** Exercised through the new path end-to-end by `tests/content-create-card-controller.spec.ts:683` (`selectionAcross('p1', 0, 'p2', 13)`): start cp 0 → index 0 → probe reads `'o'`, no trim, no clamp damage.

**Entirely separators after trimming.** `Math.max(fromUnits, utf16IndexAt(streamText, end))` at `:213` plus the two `beginUnits < finishUnits` guards make the returned pair always satisfy `start <= end` in code points; a fully-separated span collapses to `start === end`, which `captureSpan:85` answers with `null` **before** `clipFragments` (`:94`) and `buildAnchor` (`:99`). So no inverted or empty range is produced silently and no entry can be built from one. Pinned at `tests/content-selection-capture.spec.ts:201` (`refuses a selection whose normalized text is empty`) and `tests/content-create-card-controller.spec.ts:372` (no card, no write).

**The two directions agree with the boundary producer.** `streamOffsetOfBoundary` (`:166-186`) produces code points via the node's own map (`nodeCodePointIndex`), whose entries cover the whole node-local fragment extent — interior whitespace runs get one entry spanning the run, leading/trailing runs get none (`src/content/anchor/text-stream.ts:236-262`) — so a boundary inside an interior whitespace run yields the separator's code point, which the trim then removes. The two functions are consistent in both domains.

**Remaining call sites.** Grep of all of `src/content/` for `charAt`, `.slice(`, `.substring(`, `.indexOf(`, `.length`: the only stream character probes are `selection-span.ts:216, 219` (both on `*Units` values); `.substring(`/`.indexOf(` appear nowhere; `.slice(` appears once, `src/content/overlay/create-card.tsx:128`, on an `Array.from` code-point array; `.length` uses in `text-stream.ts:165-268` are separate unit and code-point counters, `locate-anchor.ts:189` compares map length to a code-point span, `selection-span.ts:176` clamps a node-local UTF-16 offset with node `data.length`. `streamStart`/`streamEnd` reach only code-point consumers (`locate-anchor.ts:138-139, 182, 195, 199-200, 208-209`; `selection-span.ts:173, 184`; `create-note.ts:164`), and the only numbers handed to `Range.setStart`/`setEnd` are `fragment.start`/`fragment.end` (`fragment-rect.ts:63-66 → 100-107`). **No remaining call site indexes the stream by UTF-16 with a code-point number.**
