## Blocking findings

1. **`docs/specs/content-overlay-ui.md:92` states an unobserved observable as shipped fact, and the shipped CSS cannot establish it.** "It renders **whole, including the lifebuoy**, at **80 CSS px** in a circular frame next to the existing title — `border-radius: 50%`, `object-fit: cover`, `object-position: center`". `object-fit: cover` into an 80×80 box crops nothing from a square source, but `border-radius: 50%` (`src/options/options.component.ts:126`) clips the element's painting area to the circle **inscribed** in that box, so the four corner regions of the 128×128 artwork are not painted — the sentence is true only if the lifebuoy lies wholly inside that inscribed circle, which is a property of the artwork. Nothing in this repo establishes it: no test reads a pixel of the file beyond `IHDR` (`tests/options-window-look.spec.ts:152-163`), no measurement covers it (the PM's measurements cover size, radius, `object-fit`, border color and load — not what survives the circular mask), the engineer disclaims the sight ("I verified the CSS numbers, not a screenshot", `docs/state/t9-02-engineer.md`, deviation 5), and the reviewer was barred from opening the image, as the previous run died in the vision encoder. So the claim currently has **no evidence path at all**. Grounding: `docs/specs/code-review-flow.md` → Rules, "Blocking only when: … tests are missing for a rule the AC lists" (the clause comes from ruling `A124`, «**whole image including the lifebuoy**», which the spec now states as a shipped property), applied by the identical precedent of the `t9-01` blocking finding 2 on this same file, plus `AGENTS.md` → Documentation Expectations. I am **not** reporting this as a spec-vs-code conflict (`blocked`): I did not open the image, so I do not assert the shipped render contradicts the sentence — I assert that it is asserted without a pin or a sight. Two cheap closes, no behavior change: **(a)** restate `:92` as a requirement whose observation Run 6 owes, in the same words `:95` already uses for the scrollbar sight; or **(b)** keep the sentence and add one byte-level assertion that the artwork's non-transparent content lies inside the circle inscribed in the source square (the test already reads the file's bytes, so this is the same technique it uses for `IHDR`).
