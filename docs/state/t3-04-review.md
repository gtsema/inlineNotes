## Stage 3 readiness — `t3-01-content-create-card`

`A36` changes what the create gate must hand `ResolvedSpans`: `src/core/entry-overlap.ts:77-82` keys existing spans in `byEntryId` and **omits a stale entry entirely**, so an `anchor_stale` turns a live entry's span into free territory for an overlapping note. Under `A24` that is the specified behavior for a genuinely stale entry, but a *transient* stale is not: the same anchor may resolve on the next paint, and the accepted create then sits on top of a span that is actually highlighted — two entries, one overlapping range, and the popup showing both. Because the locate is all-or-nothing, the create path must therefore (a) locate the candidate **and** every existing entry with `locateAnchor(root, anchor)` (`src/content/anchor/locate-anchor.ts:66-68`), which rebuilds the stream, in one synchronous pass over the same `root`, so the candidate range and `byEntryId` come from one stream; (b) never call `locateAnchorInStream` with a stream captured in an earlier frame, timer, or paint cycle — the liveness check against `root` will (correctly) report `anchor_stale` and silently free that entry's span; (c) never infer staleness from `fragments.length`: after `A36` an entry is either a complete span or absent, so a 1-fragment result is not weaker than a 3-fragment result, and `anchor.fragmentCount` stays a stored hint; (d) `ok: true` guarantees every fragment is a live descendant of the `root` passed, so the gate must not filter, count or length-check the list itself. The capture direction is unchanged by this task: build the stream once per capture, hand `buildAnchor` that same `stream.text` with half-open code-point offsets of the trimmed span, normalize with core `normalizeText` (`A26`), and do **not** import `WHITESPACE_CODE_POINTS`, `BLOCK_TAG_NAMES` or `EXCLUDED_TAG_NAMES` — they are exported for test pinning only and are read-only.

## Residual risks

- **`t3-01-content-create-card`.** `td`/`th` are now block boundaries, so a cell-crossing selection stores and counts the spaced form (`a b`), including spaces the reader never saw; the 256-char counter, the card text and the stored `entry.text` all see it, and the `A26` normalization check compares against the same spaced form — consistent, but worth a manual check on a table-heavy page. A card created over a stale entry's stored text is allowed by spec Edge Cases (`docs/specs/inline-comment-model.md:112`); if the stale entry later re-anchors, two entries cover one span — the popup must list both and deleting one must not clear the other. The `name_required` gate from the `t3-01` core review still applies unchanged.
- **`t3-02-content-highlight-tooltip`.** `anchor_not_found` and `anchor_stale` must be the same observable outcome: remove **all** of that entry's ranges from `CSS.highlights` (a previous paint must not survive a stale result), keep the row, the checkbox and delete, use one Russian string («запись недоступна») rather than one per code, and never mutate the host DOM. The `td`/`th` change means a cell-spanning entry now yields more ranges, so the frame/box set can straddle cells — a manual check on a table page. Painting must consume the list as-is (spec `content-overlay-ui.md:42`); no partial-set painting is possible after `A36`.
- **`t4-03-spa-refresh-docs`.** `A36` converts a caching bug into total highlight loss for an entry instead of a half-painted span — safer visually, but the same bug simultaneously frees that entry's span for an accidental overlapping create, which is invisible until the entry re-anchors. The SPA spec must require a full stream rebuild plus a re-locate of **every** entry after a URL change, forbid carrying a stream (or a resolved span set) across the transition, and state that a stale result must not be used as the overlap evidence for a create. Also: `npm test` now requires `dist/`, and `docs/project-profile.md:66` leaves the gate order open (remark 1).
