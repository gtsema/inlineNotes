# inlineNotes

Chrome-расширение (Manifest V3) для личных заметок к статьям: выделяешь текст на любой `http(s)`-странице, пишешь
заметку — и на этой же странице она показывается подсветкой, с тултипом при наведении и редактором на месте.
Каждый автор записей текущей страницы показан в попапе одной строкой; имя автора — в настройках. Всё хранится только
локально (`chrome.storage.local`), без сервера: собственный код расширения не делает сетевых запросов.

## Что делает собранное расширение

- Выделение текста → карточка рядом с выделением → текст заметки → `Сохранить` → подсветка выбранного текста через
  CSS Highlight API и полупрозрачная рамка вокруг неё.
- Кнопки действий в карточке и в редакторе — **без надписей, со значками** (правка `A114`): `Сохранить` — значок
  галочки, `Удалить` — значок корзины; каждая подписана по-русски через `aria-label` и `title`, поэтому подпись
  читается подсказкой и доступным именем контрола, а не его текстом. Кнопки `Отмена` нет: карточку и редактор закрывают
  `Esc` и клик вне карточки. Обе кнопки действия имеют область нажатия не меньше 24×24 пикселя; ширина карточки, кегль
  поля, счётчик и строка отказа не изменились. В попапе и в настройках кнопки остаются со словами.
- Карточка создания **не делает ни одного вызова фокуса при открытии**: страница удерживает фокус на том элементе,
  который у неё был. Дверь в карточку — **набор текста** (правка `A112`): пока карточка открыта, а фокус страницы
  находится вне shadow-хоста расширения, первая клавиша с печатным символом (кроме `Space` и любых сочетаний с
  `Ctrl` / `Meta` / `Alt`) ставит каретку в поле заметки, не отменяя самого нажатия, — символ попадает в поле. `Tab` в
  карточку не ведёт (это измерено в Chrome 157, прогон 3), и перехват `Tab` не делается: карточке не добавлен
  `tabindex`, хост не перемещён. После такого входа закрытие карточки возвращает фокус элементу страницы, а до
  контролов внутри карточки читатель доходит клавишей `Tab` в порядке `textarea` → `Сохранить`. Редактор
  своей заметки, наоборот, ставит каретку в поле заметки при открытии и возвращает фокус прежнему элементу страницы
  при закрытии, если тот ещё на странице (правка `A111`). Все вызовы фокуса идут с `preventScroll`.
- Наведение на подсвеченный текст → непрозрачный тултип с текстом заметки и именем автора: он непрозрачен с самого
  первого наведения, и ни один клик его прозрачность не меняет. Клик по тултипу **своей** заметки открывает редактор на
  месте: две кнопки со значками — `Сохранить` и `Удалить`. Клик по тултипу **чужой** заметки не меняет на странице ничего.
- Выделение текста **внутри своей** подсветки не открывает ничего. Карточка создания открывается на любом другом
  выделении — в том числе на словах, уже покрытых чужой заметкой: пересечение замечает только заметки того же автора.
  Чужие заметки только читаются: ни поля ввода, ни `Удалить` в карточке для них нет.
- Попап: список авторов текущей страницы, одна строка на автора. В строке — имя автора и число его заметок на этой
  странице через ` — ` («Вася — 10»; свои подписаны «Вы», значит «Вы — 3»), один чекбокс и одна кнопка `Удалить`. Оба
  контрола действуют на **все** заметки этого автора на этой странице: чекбокс показывает или скрывает подсветку всех
  них (флажок снят, если хотя бы одна заметка автора скрыта), `Удалить` удаляет все его заметки страницы. Строки
  упорядочены по самой ранней заметке автора, а число в строке считает и устаревшие заметки. `Удалить` в карточке
  заметки по-прежнему убирает ровно одну заметку.
- Страница настроек: одно поле «Имя» — им подписываются заметки. Если имя отсутствует или повреждено, расширение
  само генерирует случайное (8 символов) и сохраняет его; задавать его через консоль не нужно. Одно исключение: если
  хранилище не удалось даже прочитать, поле остаётся пустым с сообщением об этом, и расширение ничего не записывает.
- Без имени карточка не открывается, а попап показывает «Укажите имя в настройках» — эту строку можно нажать, она
  открывает настройки.

Подсветка не трогает DOM страницы: добавлен ровно один shadow-хост для карточек и тултипов, а правила `::highlight()`
лежат в adopted-стилях. Отдельных элементов `<style>` на странице нет.

## Установка и загрузка

```bash
npm install    # зависимости: Angular (попап и настройки) + Preact (виджеты на странице)
npm run build  # собирает готовую к загрузке папку dist/ (10 файлов: манифест + контент + попап + настройки)
npm test       # юнит-тесты: 935 тестов в 44 файлах
```

Дальше в Chrome:

1. открыть `chrome://extensions`;
2. включить **режим разработчика**;
3. нажать «**Загрузить распакованное расширение**»;
4. выбрать папку **`dist/`**.

Попап — в меню расширения; страница настроек открывается со страницы подробностей расширения на
`chrome://extensions`. После изменения кода: `npm run build`, затем «Обновить» на `chrome://extensions`.

## Разрешения

| Разрешение | Зачем оно нужно |
|---|---|
| `storage` | заметки и имя автора в `chrome.storage.local` — это единственное хранилище |
| `tabs` | **одно** чтение адреса активной вкладки, чтобы попап понимал, о какой странице он говорит |

У окна попапа нет собственного адреса, поэтому без чтения активной вкладки попап не знал бы, записи какой страницы
показывать. Из-за разрешения `tabs` Chrome **может предупредить** «**читает историю просмотров**» при добавлении
расширения; при перезагрузке уже загруженного unpacked-расширения предупреждения нет, а полный список разрешений всегда
виден на карточке расширения в `chrome://extensions`. Это не ошибка и не слежка: в манифесте нет `host_permissions` и нет
`optional_permissions`, собственный код расширения не делает сетевых запросов (в `src/` не встречается ни одного
вызова `fetch`, `XMLHttpRequest` или `WebSocket`), и данные не покидают `chrome.storage.local`: там лежат заметки, имя
автора и нормализованный ключ страницы — он является частью каждой сохранённой записи (см. «Лимиты»). Полный адрес
страницы не сохраняется: `#хэш` и метки отслеживания выбрасываются ещё до записи, а в самих ключах хранилища адрес
не встречается в открытом виде — он экранирован побайтово (`%XX`), и именно этот экранированный ключ указывает на
список записей страницы. В консоль расширение ничего не пишет (в `src/` нет ни одного `console.`). Ссылка на `XMLHttpRequest`
попадает в бандлы попапа и настроек только вместе с Angular (`@angular/common/http`), и ни один код расширения её не
вызывает. Контент-скрипт зарегистрирован только для `http://*/*` и `https://*/*`.

## Лимиты

- **256 символов** (юникод-кодовых точек) на текст заметки: счётчик `N/256`, ввод дальше блокируется, `Сохранить`
  неактивна у пустой заметки;
- **40 кодовых точек** в имени автора: счётчик `N/40`, символы вне базовой плоскости (смайлик из суррогатной пары)
  считаются по одному;
- **20 записей на страницу**: 21-я не создаётся, появляется сообщение «Достигнут лимит 20 записей на странице».

Заметка привязана к тексту страницы, а не к адресным смещениям. Ключ страницы — нормализованный адрес: из него
выбрасываются `#хэш` и метки отслеживания (`utm_*`, `gclid`, `fbclid`, `_ga`, `ref` и другие), остальные параметры
сортируются; поиск по хранилищу дополнительно падает на пару `домен + путь`, поэтому записи не теряются, если сайт
добавил или убрал параметры.

## Что в v1 не обещается

- **Одна страница в двух вкладках, сохранение в один момент.** Список записей страницы перезаписывается целиком:
  побеждает последний писатель, заметка второй вкладки может исчезнуть. Гонка не решена намеренно.
- **Повторяющийся на странице текст.** Привязка идёт по нормализованному тексту с контекстным окном; если контекст
  не различает два одинаковых предложения, заметка привязывается к **первому** вхождению в порядке документа. Выбор
  детерминирован и одинаков между перезагрузками, но это не обязательно то место, которое имел в виду читатель.
- **`iframe` и чужие shadow root вне зоны действия.** Работает только верхний фрейм; содержимое закрытых shadow root
  и кросс-доменных `iframe` нельзя ни выделить, ни подсветить.
- **Список попапа — снимок.** Пока попап открыт, он не обновляется: изменения со страницы или из другой вкладки
  видны после повторного открытия попапа.
- **Отклонённая запись из попапа молчит.** Если чекбокс или `Удалить` строки автора не получились (например, хранилище
  переполнено), попап не показывает сообщение — он перечитывает хранилище и показывает то, что в нём лежит.
- **Устаревшие (stale) записи.** Если текст заметки исчез со страницы, она не подсвечивается и не реагирует на наведение, в
  списке попапа она ничем не помечена и сама никогда не удаляется: удалить её можно только вручную, а число в строке
  автора считает и такие заметки.
- **Редактор не переносит заметку.** Новое выделение внутри редактора отвечает только на вопрос «пересечение» и ничего
  не переносит: заметка остаётся на тех словах, на которых была создана. Перенос — это `Удалить` + новая заметка.
- **Перерисовка без смены адреса.** Бесконечная прокрутка или перерисовка той же статьи адрес не меняет, поэтому
  привязка заново не ищется, пока не случится другая перерисовка: сохранение заметки, нажатие чекбокса, изменение
  хранилища в другой вкладке. Адрес страницы проверяется раз в 1000 мс, плюс события `popstate`, `hashchange` и
  `visibilitychange`; карточка открывается через 150 мс после того, как выделение перестало двигаться.
- **Страницы вне `http(s)`** — `file://`, `chrome://`, Web Store, встроенный просмотр PDF: контент-скрипт туда не
  внедряется. Попап там показывает «На этой странице подсветка недоступна», а список записей всё равно остаётся.

## Статус

- Стадии 1–7 кода **готовы**: `src/core/` (правила), `src/content/` (выделение, подсветка, карточка, редактор,
  слежение за адресом и хранилищем), `src/popup/`, `src/options/`, манифест.
- Ворота зелёные: `npm run build` собирает `dist/` (10 файлов, самодостаточная MV3-папка), `npm test` — **935 тестов
  в 44 файлах, все проходят**, `node scripts/check-agent-config.mjs` — **0 ошибок, 0 предупреждений** (130 информационных
  строк про «запланированный путь ещё не создан»).
- Прогон в реальном Chrome: пользователь **подтвердил** цикл работы на странице (выделение → карточка → заметка →
  подсветка → наведение → тултип) и экран настроек (имя задано из интерфейса, без консоли).
- Шестипозиционный проверочный список **прогнан в реальном Chrome 157.0.8103.38 (2026-11-18)** и закрыт: стоимость
  наведения на очень длинной статье, отказ «Выделение больше не найдено на странице» после того как страница заменила
  текстовый узел (карточка осталась живой, запись не сохранилась), передача «выделение своей заметки → редактор» (чужая
  заметка не открывает ничего, `A78` — заметка остаётся на своих словах), попап на реальной странице (свои — «Вы», чужие —
  серым по имени автора, `Удалить` убирает подсветку без перезагрузки, на недоступной странице — «На этой странице
  подсветка недоступна» и под ней пустой список) и перерисовка страницы от чекбокса, включая вторую вкладку той же
  страницы. Отдельно прогнан прогон 3 по разделению фокуса (правка `A111`): в реальном Chrome `Tab` после мышиного
  выделения **не попадает** в карточку — этот пункт записан как `failed`, а его причина не измерена (порядок в дереве
  страницы, хост вне `<body>` или перехват `Tab` самой страницей). Дверью в карточку стал набор текста (правка `A112`,
  задача `t6-02`): первая печатная клавиша ставит каретку в поле заметки, не отменяя нажатия. Прогон 4 перепроверит саму
  дверь, порядок контролов в живом shadow-дереве (сегодня `textarea → Сохранить` подтверждён только
  юнит-тестом) и то, теряет ли страница визуальное выделение от нажатия, которое вводит каретку. Предупреждение о
  разрешении `tabs` при перезагрузке unpacked-расширения не появлялось. Протокол и записи прогонов:
  `docs/state/browser-verification-run.md`.
- Разделение фокуса по правке `A111` (карточка не делает ни одного вызова фокуса при открытии, редактор ставит каретку в
  поле заметки и возвращает её странице) и дверь набора текста по правке `A112` в реальном Chrome **ещё не
  прогонялись**: юнит-тесты закрепляют отрицательную половину — на открытии карточки `focus` не вызывается вообще — и
  саму дверь с её незакрепляемыми ключами, а «выделение переживает открытие карточки» и «визуальное выделение может
  закончиться на нажатии, которое вводит каретку» проверяются только в браузере (прогон 4).
- Форма попапа «одна строка на автора» (`t5-06`, правки `A95` и `A108`) в реальном Chrome **ещё не прогонялась**: она
  подтверждена юнит-тестами и сборкой, а абзацы выше описывают прогон более старой формы попапа — одна строка на запись.

## Команды разработки

```bash
npm run build                                # unpacked-расширение в dist/ (манифест + контент + попап + настройки)
npm test                                     # Vitest: чистые правила src/core + контракты слоёв
npm run typecheck                            # tsc --noEmit по трём tsconfig (контент, Angular, тесты)
node scripts/check-agent-config.mjs          # механическая проверка харнесса (0 ошибок обязательно)
node scripts/check-agent-config.mjs --strict # предупреждения тоже считаются ошибками
node scripts/check-agent-config.mjs --json   # машиночитаемый отчёт
```

Порядок приёмочных ворот (`A62`) именно такой: `npm run build`, затем `npm test`, затем
`node scripts/check-agent-config.mjs`. Один из тестов проверяет содержимое `dist/`, поэтому на чистом клоне тесты до
сборки покраснеют по неверной причине. Известно-падающей базы нет: всё должно быть зелёным.

## Как устроен агентный харнесс

Пользователь общается **только с PM**; PM — основная сессия pi, `.pi/agents/project-manager.md` — эталонное тело роли.
Схема: `вопросы → декомпозиция (≤3 стадии × ≤3 задачи) → делегирование по имени роли → приёмка по артефакту и коду`.

| Роль | Кто это | Чем занимается |
|---|---|---|
| `project-manager` | read-only + делегирование | вопросы, декомпозиция, брифы, state-файлы, приёмка, ретро |
| `extension-engineer` | полный доступ + bash | весь TypeScript: `src/core`, `src/content` (Preact), `src/popup`/`src/options` (Angular), `tests` |
| `code-reviewer` | read-only, git только на чтение | ревью каждой задачи, вердикт по AC спеки |

Скиллы (`.pi/skills/`): `chrome-mv3-extension-ts`, `requirements-spec`, `delivery-planning`, `code-review-checklist`.

Спецификации (`docs/specs/`, связаны в `docs/specs/INDEX.md`):

- `inline-comment-model.md` — модель данных, ключ страницы, лимиты, авторство, якоря, пересечения.
- `content-overlay-ui.md` — карточка выделения, подсветка через CSS Highlight API, тултип/редактор, попап, настройки.
- `code-review-flow.md` — обязательное ревью, вердикты, зелёные ворота.

Источник истины по проекту: `docs/project-profile.md` (стек, лимиты, команды, runtime-модель, `timeoutMs`). Состояние
задач: `docs/state/<task-id>.md`. Ретро: `docs/retro.md`. Смоук-проверки ролей: `docs/state/smoke-project-manager.md`,
`docs/state/smoke-extension-engineer.md`, `docs/state/smoke-code-reviewer.md`.

Wiring в `.pi/settings.json`: `defaultThinkingLevel: "off"`, `skills: [".pi/skills"]`, `parallel.concurrency: 1`,
`compaction.reserveTokens: 8000`, `subagents.disableThinking/defaultThinking/maxThinking: "off"`, `agentOverrides` 1:1
с ролями. Модель нигде не закреплена: все роли `model: inherit`. Чтобы pi подхватил проектную конфигурацию, сессия
должна принять доверие к проекту (project trust) — иначе проектные роли и скиллы не загружаются.

`timeoutMs: 3600000` во всех ролях скопирован из `docs/project-profile.md` → Runtime Model. Менять его можно только
сначала в профиле, затем в ролях, в одном коммите, и после этого перегонять чекер.
