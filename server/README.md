# inlineNotes sync server

Сервер синхронизации заметок для расширения **inlineNotes**: обычный Go-сервис с базой PostgreSQL, который
хранит заметки по страницам и по авторам. Нужен он, чтобы заметками можно было делиться: один читатель отправляет
свои заметки на сервер, другой открывает ту же страницу и видит их как чужие.

Это **отдельная часть проекта**: расширение пока с сервером не связано, поэтому сервер можно запускать и проверять
сам по себе. Правила, схема и контракт API записаны в `docs/specs/sync-server.md`.

## Что нужно

Только **Docker** (движок + `docker compose` v2). Локальный Go не нужен вообще: сборка и тесты идут в контейнере
`golang:1.25-alpine`, а база — в `postgres:16-alpine`.

## Быстрый старт

```bash
# 1. Сервер + база. Первая сборка скачает зависимости образа.
docker compose up -d --build

# 2. Проверка живости.
curl http://localhost:8080/health
# {"status":"ok"}

# 3. Остановить всё и удалить том базы (данные пропадут).
docker compose down -v
```

Оба сервиса поднимаются со `healthcheck`: база готова примерно через 10 секунд после старта, сервер ждёт её
(и дополнительно повторяет попытки подключения сам), поэтому «сервер стартовал раньше базы» не ошибка.
Ожидаемая картина: `docker compose ps` показывает у `db` и `server` состояние `healthy`.

## Тесты

Тесты гоняются **в контейнере** и часть из них — против **настоящего PostgreSQL**, а не против заглушки:

```bash
docker compose run --rm test      # go test ./...
```

Профиль `test` поднимает одноразовый контейнер с Go, ждёт готовности базы и запускает весь набор. В нём выставлена
переменная `TEST_DATABASE_URL`; без неё набор тестов хранилища пропускается (не падает), а тесты обработчиков и
валидации всё равно идут. Именно поэтому `go test ./...` можно запустить и там, где базы нет.

Запустить отдельный пакет:

```bash
docker compose run --rm test go test ./internal/store/ -v
```

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATABASE_URL` | `postgres://inlinenotes:inlinenotes@localhost:5432/inlinenotes?sslmode=disable` | строка подключения к PostgreSQL |
| `PORT` | `8080` | порт HTTP API |
| `TEST_DATABASE_URL` | — | читают только тесты хранилища; пустое значение включает пропуск этих тестов |

Пример лежит в `.env.example` (для запуска образа или бинарника вне compose).

## API

Базовый путь — `/notes`. Все ответы — JSON. Ошибка — `{"error": "..."}` со статусом `400`, `404` или `500`.

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| `GET` | `/notes/page/{page_id}` | — | `200 {"notes":[...]}` |
| `POST` | `/notes/page/{page_id}` | `{"author_id":"...","notes":[...]}` | `200 {"saved":N}` |
| `DELETE` | `/notes/page/{page_id}/author/{author_id}` | — | `200 {"deleted":N}` |
| `GET` | `/notes/author/{author_id}/all-pages?limit=&offset=` | — | `200 {"notes":[...]}` |
| `GET` | `/health` | — | `200 {"status":"ok"}`, или `503`, если база недоступна |

Одна заметка в ответе:

```json
{
  "id": "aaaa1111",
  "page_id": "https://example.com/article?b=2&a=1",
  "author_id": "Анна",
  "text": "выделенный текст",
  "comment": "текст заметки, не длиннее 256 символов",
  "anchor": {"text": "...", "prefix": "...", "suffix": "...", "fragmentCount": 1},
  "created_at": "2026-11-19T12:00:00Z",
  "updated_at": "2026-11-19T12:00:00Z"
}
```

`created_at` и `updated_at` — RFC 3339 в UTC.

### Примеры

`page_id` — это тот же нормализованный адрес, что хранит расширение, и он содержит `/`, `?`, `&` и `#`, поэтому
его надо кодировать в путь (`encodeURIComponent`). `#` уезжает как `%23`.

```bash
PAGE=$(node -e "console.log(encodeURIComponent('https://example.com/article?b=2&a=1'))")

curl -X POST "http://localhost:8080/notes/page/$PAGE" \
  -H 'Content-Type: application/json' \
  -d '{"author_id":"Анна","notes":[{"id":"aaaa1111","text":"выделенный текст","comment":"моя заметка","anchor":{"text":"выделенный текст","prefix":"","suffix":"","fragmentCount":1}}]}'
# {"saved":1}

curl "http://localhost:8080/notes/page/$PAGE"
# {"notes":[{ ... }]}

curl -X DELETE "http://localhost:8080/notes/page/$PAGE/author/$(node -e "console.log(encodeURIComponent('Анна'))")"
# {"deleted":1}

curl "http://localhost:8080/notes/author/$(node -e "console.log(encodeURIComponent('Анна'))")/all-pages?limit=10&offset=0"
```

## Правила записи (коротко)

- **Заметку опознаёт тройка** `(page_id, author_id, id)`, а не `id` сам по себе. Двое могут использовать один и тот же
  `id` — это две разные строки, и записи одного автора никогда не затирают записи другого.
- **`POST` сохраняет набор заметок одного автора** (имя автора в теле запроса). Строки того же автора на той же
  странице, которых нет в запросе, **не удаляются**: для удаления есть отдельный запрос.
- **`DELETE` удаляет заметки только названного автора** и только на одной странице; другие страницы и другие авторы не
  затрагиваются.
- **`created_at` не меняется** при перезаписи, `updated_at` сдвигается вперёд.
- **`page_id` сервер не нормализует**: он принимает ключ как есть и возвращает его байт в байт.
- **`anchor` сервер не разбирает**: он только хранит его в `jsonb` и возвращает как есть.

## Что сервер проверяет

«Без аутентификации» — это не «без проверок». Тело запроса проверяется всегда, и при отказе в базу не попадает ничего:

- `author_id` не пустой (после обрезки пробелов) и не длиннее 64 символов;
- `id` не пустой и не длиннее 64 символов;
- `comment` не длиннее **256 символов** (считаются кодовые точки, а не байты);
- `text` не пустой;
- `anchor` присутствует, является корректным JSON и не равен `null`;
- в одном запросе не больше **20 заметок**;
- `limit`/`offset` — неотрицательные целые числа.

Всё это даёт `400` и `{"error":"..."}`. Незнакомое поле в теле, пустое тело и тело больше 1 МиБ тоже отклоняются.

## Безопасность: аутентификации нет

Сервер **принимает любой запрос и никого не проверяет**: ни пароля, ни токена, ни ограничения частоты запросов.
Практические последствия, которые надо знать до развёртывания:

- любой, кто дотянется до порта, **прочитает все заметки всех страниц**;
- любой может **удалить заметки любого автора**, просто назвав его в пути;
- CORS открыт (`Access-Control-Allow-Origin: *`), чтобы будущий контент-скрипт мог обращаться к серверу со страницы.

Это осознанное решение, а не недосмотр. Разворачивать сервер стоит **только в доверенной сети** (локально, в личной
сети или за VPN). Если сервер когда-нибудь понадобится выставить в интернет, без аутентификации этого делать нельзя —
её надо добавить отдельной задачей.

## Структура

```
cmd/server/main.go        точка входа: переменные окружения, пул, миграции, HTTP-сервер
internal/api/             обработчики, маршруты, JSON, CORS
internal/store/           доступ к PostgreSQL, миграции, запросы (+ тесты против настоящей базы)
internal/model/           Note, типы запросов/ответов, валидация (+ тесты)
migrations/               .sql, вшитые в бинарник
Dockerfile                многоступенчатая сборка: golang:1.25-alpine -> alpine
docker-compose.yml        сервер + postgres:16-alpine, healthcheck, именованный том
.env.example              DATABASE_URL, PORT
```

## Ограничения текущей версии

- Интеграции с расширением **нет**: ни кнопки синхронизации, ни сетевых запросов из расширения.
- Конфликты правок не сливаются: при совпадении тройки побеждает последняя запись.
- Чужие заметки **на сервере** удалить нельзя (попап расширения удаляет чужие заметки только локально).
- Раздел `all-pages` реализован и протестирован, но расширение его пока не вызывает — это задел на будущий экран
  «мои заметки».
- Схема создаётся автоматически при старте; отдельного инструмента миграций и отката версий нет.
